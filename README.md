# Clip Downloader

Windows単体で動く動画ダウンロードアプリ。StudioやWSLの起動は不要です。

## 起動

`dist\build-日時\ClipDownloader\ClipDownloader.exe` を起動します（フォルダ全体が必要）。最新パスは `dist\latest-build.json` で確認できます。
開発版は以下で起動できます。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

## 使い方

1. 単体動画のURLを1行に1件入力します（複数可、追加1回あたり100件まで）。
2. 保存先（初期値 `D:\Youtube`）と720p／1080p／最高画質を選択します。
3. 必要なら「指定区間のみ」にチェックし、開始・終了を入力します。
   `01:23:45.5`、`23:45.5`、`85.5` の形式に対応します。
4. 同時DL数（1〜4、初期値2）を選び、「キューに追加・開始」を押します。
   実行中もURLの追加ができ、動画ごとの進捗が一覧に表示されます。
   選択した動画のキャンセル、または「すべて停止」ができます。
5. 完了後「保存フォルダを開く」でMP4を確認します。

画質指定は上限です。元動画の解像度が低い場合は拡大しません。
毎回別の `clip-日時-ID` フォルダを作り、既存動画を上書きしません。
取得URL・タイトル・指定区間・完成ファイルを同フォルダの `clip.json` に保存します。
映像と音声が分かれている場合は結合し、MP4へ再エンコードなしでまとめます。
指定区間の境界はキーフレーム等の影響で少しずれる場合があります。
途中で止めたファイルは専用フォルダに残します。再試行は新しい取得として実行します。
速度・残り時間は取得元から情報が得られる段階で表示します。
結合中や情報取得中は処理中表示になります。

保存先・画質・並列数は `%LOCALAPPDATA%\ClipDownloader\settings.json` に記憶します。
Cookie認証、会員限定動画、プレイリスト一括取得は未対応です。Studio連携は後述の設定が必要です。
公開動画でも取得元の制限や仕様変更により失敗することがあります。
その場合はログを確認し、必要に応じてyt-dlpと依存を更新してください。

## 開発・検証

Windows版uv・Gitを使います。Python 3.12と依存は `.venv` に分離し、WSLと共有しません。

```powershell
uv run --locked clip-downloader --check
uv run --locked clip-downloader --smoke
uv run --locked ruff check .
uv run --locked python -m unittest discover -s tests -v
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
```

テストはローカルHTTPサーバーと生成した短い動画を使い、外部動画を大量取得しません。
UIテストはWindows上で短時間ウィンドウを表示します。
`build.ps1` は毎回 `dist\build-日時\ClipDownloader` に別版を作り、起動中のアプリを終了させません。
最新exeのパスは `dist\latest-build.json` に記録します。

## 構成・依存

- `src/clip_downloader/app.py`: Tkinter画面、設定、プロセス管理
- `src/clip_downloader/download.py`: 入力検証、yt-dlp実行、取得情報保存
- `src/clip_downloader/jobs.py`: 並列数・個別キャンセル・待機キュー
- `src/clip_downloader/history.py`: 完了ファイル照合とプロセス間ロック
- `tests/`: 全編／区間取得、重複防止、並列制御、キャンセル、エラー復帰の検証
- `scripts/`: Windows用セットアップ、起動、exeビルド

`yt-dlp[default]` のEJSとDenoを同梱し、別途Node.jsの導入は不要です。
FFmpegはimageio-ffmpegのWindows wheelから供給します。
[yt-dlpのEJS構成](https://github.com/yt-dlp/yt-dlp/wiki/EJS)

依存更新は `uv lock --upgrade` → `uv sync --locked` → テスト → exe再ビルド。
`pyproject.toml`・`uv.lock`・`.python-version` はGit管理します。
動画・Cookie・認証情報・個人設定・ログ・仮想環境・exeはGit管理しません。

配布前に同梱依存のライセンス・告知を確認し、Python未導入のWindowsでも検証してください。
現時点のexeはこのPCでの利用・動作確認用です。

## 取得済みチェック

「取得済みをスキップ」は初期状態で有効です。選択した保存先配下の `clip.json` と
完成MP4の存在を照合します。以前のバージョンで取得した動画も対象です。
YouTubeの動画IDを使うため、短縮URLや `t=` 付きURLでも同じ動画として扱います。
全編と区間は別扱いで、区間は開始・終了が一致する場合のみスキップします。
画質が違っても同じ動画・区間はスキップするため、高画質で取り直す場合はチェックを外します。
実ファイルが削除・空・記録されたサイズと不一致の場合は再取得します。
同じ動画を並列キューや別ウィンドウから追加しても、保存先が同じなら重複取得を防ぎます。

対象はこのアプリの完了情報付き動画です。外部ツールの動画や、保存先の外の動画は
自動では照合しません。ファイル名だけで同じ内容か判定することは避けています。
新しく作る `.clip-downloader/locks` は動作管理用です。中身のロックは終了・強制停止時に
OSが解除します。空に近い管理ファイルは残りますが、次回の取得を妨げません。

同時DL数を減らしても実行中の動画は停止せず、次の開始から上限を守ります。
区間・保存先・画質の変更は新たにキューへ追加する項目だけに適用されます。

## ダウンロード済みタブ

「ダウンロード済み」タブには、現在選択している保存先内の取得完了動画を一覧表示します。
このアプリの `clip.json` と実際のMP4を照合し、削除・未完成のファイルは除外します。
以前のバージョンで取得した動画も表示できます。外部ツールの動画は対象外です。

- 行をダブルクリックするとWindowsの既定の動画プレーヤーで再生します。
- キーボードで選択してEnter、または「再生」ボタンでも開けます。
- タイトル／ファイルパスで検索できます。
- 「フォルダを開く」で選択動画の保存場所を表示します。
- タブを開いたとき、DL完了時、「更新」ボタンで一覧を読み直します。
- ダウンロード画面の保存先を変更すると一覧の対象も変わります。

一覧からの通常再生は既定アプリ、範囲クリップは内蔵プレーヤーを使用します。MP4の既定アプリが未設定の場合は
Windows側で動画プレーヤーを選択してください。

右クリックで対象を選択し、「削除（ごみ箱へ）」「プロパティ」を使えます。
削除前に確認し、動画だけを移動します。完了情報は残すため、ごみ箱から戻すと再表示されます。
プロパティにはタイトル、パス、サイズ、区間、保存日時、元URLを表示します。

## ローカル動画の範囲クリップ

ダウンロード済みタブで動画を選び「範囲クリップ」（右クリックでも可）を押します。
アプリ専用ウィンドウで動画プレビューが開きます（外部ブラウザは開きません）。再生・シークして「ここから」「ここまで」を押すと、
現在の再生位置を開始・終了に設定できます。「選択範囲を再生」で確認して「切り出し開始」。
±5秒移動、時:分:秒での直接入力にも対応しています。
右クリックの「時刻入力でクリップ」から従来の入力画面も使えます。
選択したファイルの先頭が0秒です。区間取得済みの動画でも元配信の時刻ではありません。
元動画を残して、現在の保存先の `local-*` フォルダへ別MP4を作成します。
フレーム単位で切り出すためH.264/AACへ再エンコードします。再DLやネット接続は不要です。
進捗確認・キャンセルはダウンロードタブの共通キューで操作できます。
完了したクリップは動画一覧に追加されます。DL済み判定ではローカルクリップを除外します。

プレビューはPC内の127.0.0.1で提供し、動画は外部送信しません。アプリを終了すると停止します。
内蔵WebView2で対応していない映像・音声形式は再生できない場合があります。

アプリ内プレーヤーにはpywebviewとMicrosoft Edge WebView2 Runtimeを使用します。
起動できない場合はWebView2 Runtimeを確認してください。時刻入力での切り出しも引き続き使えます。

## YouTube検索

「YouTube検索」タブでキーワードを入力し、Enterまたは「検索」を押します。
10・20・50件を選択できます。APIキーは不要です。
タイトル・チャンネル・再生時間とサムネイルを表示します。検索と画像取得は
バックグラウンドで行い、検索中もダウンロードキューを操作できます。
画像が取得できなくても動画は選択できます。ライブ中・配信予定は時刻欄に表示します。

Ctrl / Shiftで複数選択し「選択動画をDL欄へ追加」を押すと、既存のURLを残して
ダウンロード画面へ移動します。同じURLは追加しません。この操作だけではDLしません。
画質・保存先・必要な区間を確認して「キューに追加・開始」を押してください。
ダウンロード後は「ダウンロード済み」から動画を見ながら範囲クリップできます。
ダブルクリックまたは「YouTubeで開く」は既定ブラウザで元動画を開きます。

検索はyt-dlpのメタデータ取得を利用し、動画本体は取得しません。検索順はYouTube側の
結果に依存し、ブラウザのログイン状態・検索履歴は使いません。失敗時は画面に理由を表示し、
再検索できます。サムネイル表示にはPillowを使用します。

### 切り抜きから元動画URLを確認

検索結果を1件選び「元動画URLを確認」を押すと、その動画の説明欄を取得します。
動画本体はDLせず、検索全件の説明欄を自動取得することもありません。
説明欄のYouTube動画URLを候補として、前後の記載と説明欄全文を表示します。
候補を選択して「URLコピー」または「DL欄へ追加」を使えます。
短縮URL・watch・live・shorts形式に対応し、同じ動画の重複と選択動画自身は除外します。
候補URLは動画先頭のURLに統一します。

説明欄には関連動画や宣伝も含まれます。元配信だと自動断定せず、出典の記載を確認して
選択してください。リンクがない場合は特定できない旨を表示します。取得失敗時は再取得できます。

## Windows単体の文字起こし・範囲解析

「ダウンロード済み」で動画を選び「文字起こし」を押すか、「文字起こし・解析」タブの
「MP4を選択」で既存動画を指定します。全編または「指定範囲のみ」を選んで時:分:秒を入力し、
「解析キューに追加」。ダウンロードとは別のキューで1件ずつ処理し、選択行を停止できます。
同じ設定の実行中・待機中解析は重複追加しません。終了時は解析も停止対象です。

- faster-whisperをWindows上で実行します。WSL・Studio・APIキーは不要です。
- 既定モデルは `large-v3`。小さいモデルは高速ですが、認識結果を確認してください。
- `auto` はNVIDIA GPUと必要DLLがあればCUDA、なければCPU（int8）。使用先は進捗・JSONに記録します。
  Windows版exeにはCUDA 12のcuBLAS・ランタイム・cuDNN 9を同梱します。
  NVIDIAドライバーはPC側に必要です。開発環境も `uv sync --locked` でGPU用依存を取得します。
  同梱DLLを優先し、他アプリのPATHにある古いCUDAライブラリへの依存を避けます。
  `cuda`指定時に実行環境が不足していればエラーを表示します。
  CPU解析も利用できますが、長尺のlarge-v3は時間がかかります。
  [faster-whisper公式のGPU要件](https://github.com/SYSTRAN/faster-whisper#gpu)
- 初回のみモデルを取得し、`%LOCALAPPDATA%\ClipDownloader\models` にキャッシュします。
  モデル読み込み・初回取得中も別プロセスで処理し、画面は操作できます。
- 日本語固定・自動話者分離なし。字幕の `speaker` は未割当です。
- 「認識のヒント」は1行1語でWhisperのhotwordsへ渡します。
  「認識後の補正」は `ミオシャ => ミオしゃ` の形式。既定はこの1件だけです。
  ルールは長い一致を優先し、置換結果の再置換はしません。
  「設定を保存」でモデル・実行先・ヒント・補正ルールを、動画選択やキュー追加なしで保存できます。
  次回起動時に復元します。追加済み・実行中の解析の設定は変更しません。
  キュー追加時の設定保存も引き続き行います。入力だけでの自動保存ではありません。

結果は **選択動画のフォルダ\analysis\日時-ID\analysis.json** と **subtitles.srt**。
繰り返し実行しても既存の結果を上書きせず、範囲ごとに独立して保存します。
時刻は範囲の先頭を0にせず、**選択したMP4の先頭からの秒数**です。
区間DL済み・切り出し済みMP4では、元配信の時刻とは異なります。既存の取得情報は
`source_metadata` に残し、キーフレーム境界の誤差を無視した元配信時刻への変換はしません。

JSONにはファイルパス・サイズ・更新時刻、解析範囲、モデル・実行先・補正設定、補正前の
`raw_text` と補正後の `text`、単語時刻を保存します。単語の文字列は認識時の原文です。
JSONの完成保存を完了判定に使います。失敗時はerror.txt、強制停止時は一時音声などが
解析用フォルダに残る場合があります。元MP4を変更・削除しません。
「結果フォルダ」から保存先を開けます。アプリ再起動後もファイルは残ります。
Studioへの取り込みは後述の「解析履歴とStudio連携」を参照してください。

実音声の任意検証は `CLIP_ANALYSIS_SAMPLE` に短い日本語MP4の絶対パスを指定して
`uv run --locked python -m unittest discover -s tests -p test_analysis.py -v`。
通常テストではモデル取得を行いません。

解析一覧には「解析時間」（時:分:秒）と「完了日時（作成日時）」を表示します。
解析時間はキュー待機を除き、処理開始から音声抽出・モデル取得／読込・文字起こし・補正を
終えるまでです。初回モデルDLの時間も含みます。JSONにも `started_at`・`completed_at`・
`elapsed_seconds` を保存し、`created_at` は完了日時と同じ値です。画面の日時はPCのローカル時刻です。
未完了の行は「—」。旧版で作成した結果の所要時間は遡って計測できません。

## 解析履歴とStudio連携

「解析履歴」タブは現在の保存先配下の完成済み `analysis.json` を読み込みます。
「再読み込み」で更新し、保存先以外の結果は「解析JSONを選択」から追加できます。
旧版の結果も対象です。記録のない解析時間は「不明」、未完成・壊れたJSONは除外します。

行の「Studioで開く」をクリック、または行を選んで上のボタン／Enterで開きます。
初回のみStudioへ字幕と元動画情報を取り込み、話者登録用音声を用意します。再解析はしません。
再度開くと同じStudio解析を使い、編集済み字幕・トピックは上書きしません。
元動画が移動・変更された場合や同じ解析IDのJSONが変更された場合はエラーを表示します。

Studio連携を使う場合は、解析履歴の「WSLのStudioパス」にStudioのWSL上の絶対パスを入力し、
「接続先を保存」を押します。EngineはStudioの隣の `vtuber-clip-engine/.venv` に配置します。
Studioが停止中なら既存の環境を起動し、動作中ならそのまま接続します。
ブラウザは `http://localhost:4174/?job=...&view=browse` を開きます。
Windowsのドライブ文字付きパスに対応し、UNCネットワークパスは未対応です。
取り込み中もDL・解析は継続します。設定ファイルや元解析JSONを書き換えません。


### Studioデータを別の環境へ持ち運ぶ

新規取り込みでは、解析JSONの隣の `studio/<ID>/` に元動画・字幕・トピック・解説画像・音声・
描画素材・表示設定をまとめます。完成MP4とCCもこの中に保存します。初回は元動画をコピーするため
追加の空き容量が必要です。既存のWSL解析や旧Windows保存データは自動移行しません。

保存を済ませて編集・出力を終了してから、`studio-package.json` を含むフォルダ全体をコピーします。
移動先で「解析履歴」→「解析・Studioデータを開く」から `studio-package.json` を選んでください。
対応版Studio/Engineの導入は必要です。「WSLのStudioパス」で移動先のインストール先を指定し、
「接続先を保存」で記憶できます。EngineはStudioと同じ親フォルダに配置します。
ブラウザに保存したプレビューのレイアウト・テレビ枠・縦型字幕と解説の位置も、新規データでは
Studioデータ側に保存されます。YouTube認証や解析モデル、既存のプロジェクト一覧・声紋ライブラリ
全体は含めません。割り当て済みの話者名・字幕・生成済みナレーションは保持されます。

## 字幕の時刻推定（2026-10-17）

新しい解析はVADによる無音区間の連結を行わず、元音声の時間軸でWhisperを実行します。
ラップ・笑い声・同時発話を含む実素材で、長い無音を前の字幕へ巻き込む問題が軽減しました。
発話時刻の推定誤差や誤認識がなくなる保証はありません。無音の多い動画は処理が遅くなります。
解析JSONの `timing_policy: original_audio_clock_v1` と `vad_filter: false` で方式を確認できます。
既存解析・Studioの手編集済み字幕は変更しません。旧結果へ一律の秒数補正は行わず、必要なら別解析として実行します。

### 解析とStudioで共用するAAC動画

解析前に音声をAAC（192 kbps）へ変換し、映像は再圧縮せずコピーします。元MP4は保持し、元動画の隣の `analysis-media/` に再生・解析用MP4を保存します。部分解析でも動画全体の時刻を維持します。元ファイルのパス・サイズ・更新日時が同じで、変換済みファイルのサイズ・更新日時が一致すれば再利用します。変換に失敗した場合は解析を停止し、該当フォルダのログに記録します。

新しい解析JSONの `source_file` はAAC動画を指し、Studioもその動画を取り込みます。元動画は `original_source_file` に記録します。既存の解析JSONや編集中のStudioデータは変更しません。`analysis-media/` は解析結果が参照する実データなので、解析JSONだけを残して削除しないでください。

### 検索結果の右クリックメニュー

YouTube検索の結果と元動画URL候補の一覧では、行を右クリックして「DLキューに追加」「DL欄に追加」「元動画URLを確認」「YouTubeで開く」を選べます。キュー追加は現在の保存先・画質・区間・重複スキップ設定を使用して開始し、DL欄に入力中のURLは保持します。検索の複数選択ではキュー／DL欄への一括追加が可能です。元動画確認・ブラウザ表示は1件選択時のみ利用できます。

### 複数区間を1本に結合

「ダウンロード済み」から動画を見ながら範囲クリップを開き、開始・終了を指定して「区間を追加」を押す。最大100区間まで登録できる。登録済みの時刻ボタンを押すとその区間へシークし、開始・終了欄に読み込む。「選択区間を再生」で確認し、時刻を変更して「選択区間を更新」で確定する。↑・↓で結合順を変更でき、「削除」で不要な区間を外せる。

「登録区間を結合して切り出し」で一覧の上から順に1本のMP4を出力する。区間の重複・逆順もそのまま出力する。区間を登録しているときは、未登録・未更新の入力値は出力に含まれない。登録区間がなければ従来どおり入力中の1区間を切り出す。「時刻入力でクリップ」の簡易ダイアログは従来の単一区間用。

元動画は残り、出力先は設定した保存先の `local-日時-ID/`。結合結果はダウンロード済み一覧に1本として表示され、`clip.json` の `requested_ranges` に元ファイル内の区間を順番付きで保存する。画面を閉じる前の未出力の区間リストは保存しない。中間ファイルでは音声をPCMで保持し、結合時にAACへ変換する。区間ごとのAACエンコード遅延の累積を避け、映像は結合時に再圧縮しない。

検証: `python -m unittest discover -s tests -p test_local_clip.py -v` と `test_preview.py`。画面検証は既存Playwright環境で `node scripts/check-multi-clip.cjs PAGE_HTML TEST_MP4 [BROWSER_ENV_MODULE]` を実行する（APIは模擬、動画は実デコード）。

### Codexで日本語チェック・修正

「解析履歴」で対象を選択し「Codexで日本語チェック・修正」を押す。WSL側のログイン済みCodex CLIを使って文章をチェックし、明確な誤字・誤認識を修正して保存する。音声は確認せず、不確かな箇所は要確認として残す。処理中は対象字幕の編集を控え、完了後にStudioを再読み込みする。「修正結果」で時分秒・話者・修正前後を確認できる。

未取り込みの解析はanalysis.json、Studioで編集済みなら最新result.jsonの日本語本文だけを更新する。非表示字幕は除外し、時刻・話者・翻訳・解説等は保持。バックアップとレポートは対象フォルダのcodex-reviews/日時-ID/に保存する。認識時のsubtitles.srtは原記録として残る。Studio取り込みには修正済みJSONが使われる。処理中に変更されたデータは上書きせず中止する。認証失敗時はWSLでcodex loginを確認する。ログは各バッチのcodex.log。

この機能には対応版Studioのscripts/review-downloader-analysis.pyが必要。接続先は「WSLのStudioパス」を使用する。CLI仕様は https://learn.chatgpt.com/docs/developer-commands#codex-exec を参照。

解析履歴の行を右クリックすると「Codexで日本語チェック・修正」「Studioで開く」「修正結果を開く」「結果フォルダを開く」を選べる。右クリックした行が操作対象になる。Codexチェック・Studio取り込みの処理中は、重複起動する項目を無効にする。

「Codexチェック」列は保存済みレポートのapplied=trueを確認し、「未チェック」「チェック済み」「チェック済み・要確認○件」を表示する。これはチェック完了履歴であり、その後の手編集まで確認済みと保証するものではない。新しい試行が失敗していても過去の完了履歴は残す。元の解析フォルダのstudio配下へ取り込んだ場合は元解析のチェック履歴も参照する。「修正結果」は選択行のレポートを開く。アプリを再起動した場合も再読み込みで復元される。
